## 2024-06-11 - Fixed Layout Thrashing in Homepage Hero Animation
**Learning:** The codebase contains a custom interactive hero element that updates CSS custom properties via `requestAnimationFrame` (`renderHeroWidth`), but reads DOM layout synchronously via `getBoundingClientRect()` on every `pointermove` event (`updateHeroWidth`). This read/write interleaving across events and animation frames forces the browser to recalculate layout on every mouse move, causing severe layout thrashing (synchronous layout).
**Action:** Always cache bounding boxes (like `getBoundingClientRect()`) outside of high-frequency events (like `pointermove`, `scroll`, or `resize`). Update the cache specifically on events like `pointerenter`, `resize`, or `scroll` where the dimensions or position might genuinely change, but do not read layout during the high-frequency event handler itself.
