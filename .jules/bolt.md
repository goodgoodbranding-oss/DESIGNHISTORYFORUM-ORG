## 2024-06-24 - Layout Thrashing in Pointer Events
**Learning:** This codebase uses direct DOM manipulation in `requestAnimationFrame` while listening to frequent events like `pointermove`. Specifically, reading `getBoundingClientRect()` inside a `pointermove` handler while writing to CSS properties (`style.setProperty`) in `requestAnimationFrame` creates severe layout thrashing, as the browser is forced to synchronously recalculate layout on every mouse movement.
**Action:** Always check event listeners that fire frequently (`pointermove`, `mousemove`, `scroll`, `resize`) for DOM reads (like `getBoundingClientRect()`, `offsetWidth`, `clientHeight`). Cache these reads and update the cache strategically (e.g., on `pointerenter`, `resize`, or debounced `scroll`) to decouple layout reads from animation-driven layout writes.
